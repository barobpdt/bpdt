# DDL to SQLAlchemy Model Generator

DDL 스키마를 파싱하여 SQLAlchemy 모델을 자동으로 생성하는 도구들입니다.

## 📋 개요

이 프로젝트는 다음과 같은 방법들로 SQLAlchemy 모델을 생성할 수 있습니다:

1. **커스텀 DDL 파서** (`ddl_to_sqlalchemy.py`) - DDL 파일을 직접 파싱
2. **sqlacodegen 래퍼** (`sqlacodegen_wrapper.py`) - 기존 데이터베이스에서 모델 생성
3. **다양한 데이터베이스 지원** - MySQL, PostgreSQL, SQLite, Oracle, MSSQL


### 방법 2: sqlacodegen 래퍼 사용

#### 기존 데이터베이스에서 모델 생성

```bash
# MySQL 데이터베이스
python sqlacodegen_wrapper.py \
    --database "mysql+pymysql://user:password@localhost/dbname" \
    --output models.py

# PostgreSQL 데이터베이스
python sqlacodegen_wrapper.py \
    --database "postgresql://user:password@localhost/dbname" \
    --output models.py

# SQLite 데이터베이스
python sqlacodegen_wrapper.py \
    --database "sqlite:///database.db" \
    --output models.py
```

#### DDL 파일에서 모델 생성

```bash
python sqlacodegen_wrapper.py \
    --ddl example_ddl.sql \
    --output models.py
```

#### 고급 옵션

```bash
# 특정 테이블만 생성
python sqlacodegen_wrapper.py \
    --database "mysql+pymysql://user:password@localhost/dbname" \
    --tables "users,products,orders" \
    --output models.py

# 뷰, 인덱스, 제약조건 포함
python sqlacodegen_wrapper.py \
    --database "mysql+pymysql://user:password@localhost/dbname" \
    --include-views \
    --include-indexes \
    --include-constraints \
    --output models.py
```

## 🔧 지원하는 기능

- **실수형**: `FLOAT`, `DOUBLE`, `DECIMAL`, `NUMERIC`
- **문자형**: `VARCHAR`, `CHAR`, `TEXT`
- **날짜형**: `DATE`, `DATETIME`, `TIMESTAMP`
- **기타**: `BOOLEAN`, `JSON`, `BLOB`

#### 지원하는 제약조건
- `PRIMARY KEY`
- `FOREIGN KEY`
- `UNIQUE`
- `NOT NULL`
- `DEFAULT`
- `AUTO_INCREMENT`
- `COMMENT`

#### 지원하는 구조
- 테이블 정의
- 컬럼 정의
- 외래키 관계
- 인덱스
- 주석

#### 지원하는 데이터베이스
- MySQL
- PostgreSQL

- Oracle
- Microsoft SQL Server

#### 옵션들

- `--include-views`: 뷰 포함

- `--include-constraints`: 제약조건 포함
- `--include-joined`: 조인된 테이블 포함
- `--include-inflect`: 단수형 변환 포함

## 📝 생성되는 모델 예시

### 입력 DDL (example_ddl.sql)
```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '사용자명',
    email VARCHAR(100) NOT NULL UNIQUE COMMENT '이메일',
    password_hash VARCHAR(255) NOT NULL COMMENT '비밀번호 해시',
    is_active BOOLEAN DEFAULT TRUE COMMENT '활성 상태',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '생성일시'
);
```

### 생성되는 SQLAlchemy 모델
```python
"""
Auto-generated SQLAlchemy models from DDL
Generated by DDL to SQLAlchemy Generator
"""

from sqlalchemy import Column, Integer, String, Text, Boolean, Date, DateTime, Numeric, BigInteger, SmallInteger, Float, JSON, LargeBinary, ForeignKey
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import relationship
from datetime import datetime

Base = declarative_base()

class Users(Base):
    __tablename__ = "users"

    # 사용자명
    id = Column(Integer(), primary_key=True, autoincrement=True)
    # 사용자명
    username = Column(String(50), nullable=False, unique=True)
    # 이메일
    email = Column(String(100), nullable=False, unique=True)
    # 비밀번호 해시
    password_hash = Column(String(255), nullable=False)
    # 활성 상태
    is_active = Column(Boolean(), default=True)
    # 생성일시
    created_at = Column(DateTime(), default=datetime.now)

    def __repr__(self):
        return f"<Users(id={self.id})>"
```

## 🛠️ 고급 사용법

### 1. 관계 설정 자동 생성

외래키가 있는 테이블의 경우 관계 설정이 자동으로 생성됩니다:

```python
class OrderItems(Base):
    __tablename__ = "order_items"

    id = Column(Integer(), primary_key=True, autoincrement=True)
    order_id = Column(Integer(), ForeignKey('orders.id'), nullable=False)
    product_id = Column(Integer(), ForeignKey('products.id'), nullable=False)
    quantity = Column(Integer(), nullable=False)
    unit_price = Column(Numeric(10, 2), nullable=False)
    total_price = Column(Numeric(10, 2), nullable=False)

    # 자동 생성된 관계
    orders = relationship("Orders", back_populates="order_items")
    products = relationship("Products", back_populates="order_items")
```

### 2. 커스텀 타입 매핑

필요에 따라 타입 매핑을 수정할 수 있습니다:

```python
# ddl_to_sqlalchemy.py의 _parse_type 메서드 수정
def _parse_type(self, type_str: str) -> Tuple[str, Optional[int], Optional[int], Optional[int]]:
    type_str = type_str.upper()
    
    # 커스텀 타입 매핑 추가
    if 'UUID' in type_str:
        return 'String(36)', 36, None, None  # UUID를 String(36)으로 매핑
    
    # 기존 로직...
```

### 3. 모델 후처리

생성된 모델에 추가 기능을 넣을 수 있습니다:

```python
# 생성된 모델에 메서드 추가
class Users(Base):
    __tablename__ = "users"
    
    # ... 기존 컬럼들 ...
    
    @property
    def full_name(self):
        return f"{self.first_name} {self.last_name}"
    
    def is_admin(self):
        return any(role.name == 'admin' for role in self.roles)
```

## 🔍 문제 해결

### 일반적인 문제들

#### 1. DDL 파싱 오류
```
Error: No tables found in DDL file
```
- DDL 파일의 문법을 확인하세요
- CREATE TABLE 문이 올바른 형식인지 확인하세요

#### 2. 데이터베이스 연결 오류
```
Error: (pymysql.err.OperationalError) (2003, "Can't connect to MySQL server")
```
- 데이터베이스 서버가 실행 중인지 확인하세요
- 연결 정보(호스트, 포트, 사용자명, 비밀번호)를 확인하세요

#### 3. 권한 오류
```
Error: (pymysql.err.OperationalError) (1142, "SELECT command denied")
```
- 데이터베이스 사용자에게 적절한 권한을 부여하세요

# FastAPI + Supabase 테이블 생성 기능

이 프로젝트는 Pydantic 모델을 기반으로 Supabase 테이블을 자동 생성하는 기능을 제공합니다.

## 주요 기능

### 1. Pydantic 모델 기반 테이블 스키마 생성
- `User` 클래스의 필드 정보를 분석하여 PostgreSQL 테이블 스키마를 자동 생성
- 타입 매핑: Python 타입 → PostgreSQL 타입
- 제약 조건 자동 설정 (Primary Key, Unique, NOT NULL 등)

### 2. SQL DDL 자동 생성
- 생성된 스키마를 기반으로 완전한 SQL CREATE TABLE 문 생성
- Supabase 대시보드에서 바로 실행 가능한 SQL 제공

### 3. API 엔드포인트
- `POST /generate-schema`: 테이블 스키마 생성
- `GET /table-info`: 현재 테이블 정보 조회
- `POST /create-table`: 테이블 생성 (스키마 생성)

## 사용 방법

### 1. 서버 실행

## User 모델 분석

### 현재 User 클래스 구조
```python
class UserBase(BaseModel):
    name: str                    # text NOT NULL
    email: EmailStr             # text UNIQUE NOT NULL
    age: Optional[int] = None   # integer
    city: Optional[str] = None  # text

class User(UserBase):
    id: int                     # bigint PRIMARY KEY
    created_at: datetime        # timestamptz NOT NULL DEFAULT now()
```

### 생성되는 SQL DDL
```sql
CREATE TABLE IF NOT EXISTS users (
    name text NOT NULL,
    email text NOT NULL,
    age integer,
    city text,
    id bigint NOT NULL DEFAULT identity,
    created_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (id),
    UNIQUE (email)
);
```

## 타입 매핑

| Python 타입 | PostgreSQL 타입 | 설명 |
|-------------|----------------|------|
| `str` | `text` | 문자열 |
| `int` | `integer` | 정수 |
| `float` | `numeric` | 실수 |
| `bool` | `boolean` | 불린 |
| `datetime` | `timestamptz` | 타임스탬프 |
| `EmailStr` | `text` | 이메일 (UNIQUE 제약) |
| `Optional[Type]` | `Type` | 선택적 필드 |

## 제약 조건 자동 설정

### Primary Key
- `id` 필드: 자동으로 PRIMARY KEY로 설정
- 타입: `bigint` (자동 증가)

### Unique 제약
- `email` 필드: 자동으로 UNIQUE 제약 설정
- `EmailStr` 타입: 자동으로 UNIQUE 제약 설정

### NOT NULL 제약
- 필수 필드: 자동으로 NOT NULL 설정
- `id`, `created_at`: 자동으로 NOT NULL 설정

### 기본값
- `id`: `identity` (자동 증가)
- `created_at`: `now()` (현재 시간)

## 확장 가능성

### 새로운 모델 추가
1. Pydantic 모델 정의
2. `TableSchemaGenerator.create_table_from_model()` 호출
3. 자동으로 스키마 및 SQL 생성

### 커스텀 타입 매핑
`TableSchemaGenerator.TYPE_MAPPING` 딕셔너리에 새로운 타입 매핑 추가

### 커스텀 제약 조건
필드명이나 타입을 기반으로 추가 제약 조건 설정 가능

## 주의사항

1. **Supabase 권한**: 테이블 생성에는 적절한 데이터베이스 권한이 필요합니다.
2. **기존 테이블**: 이미 존재하는 테이블은 `CREATE TABLE IF NOT EXISTS`로 보호됩니다.
3. **스키마 변경**: 기존 테이블의 스키마 변경은 별도의 ALTER TABLE 문이 필요합니다.
4. **데이터 손실**: 테이블 삭제 시 데이터가 손실될 수 있으므로 주의하세요.
