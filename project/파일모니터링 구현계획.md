# Real-time File Monitoring Feature

파일의 내용이 변경될 때마다 채팅창에 새로운 내용을 자동으로 브로드캐스트하여 실시간 로그를 볼 수 있는 기능입니다.

## User Review Required
- 이 기능은 파일의 경로를 서버에 전달하므로, 서버의 로컬 경로를 읽을 수 있습니다. 보안상 이전 `/cmd` 명령처럼 **로그인된 관리자(JWT 토큰 보유자)**만 이 모니터링을 시작/중지할 수 있도록 권한을 제한할 계획입니다.
- 추가된 내용만 읽기 위해 파일의 마지막 크기(`size`)를 추적하고, 파일이 수정(change)될 때 커진 크기만큼만 스캔하여 웹소켓으로 전송합니다.

## Proposed Changes

### `server.js`
- **[NEW] API Endpoint (`/api/monitor`)**
  - POST 요청으로 `{ action: 'start' | 'stop', targetFile: '경로' }`를 받습니다.
  - Jwt 토큰을 검사하여 권한을 확인합니다.
  - `fs.watch`를 사용하여 파일 변경을 감지하고, 변경 이벤트 발생 시 `fs.readSync` 등을 이용해 새로 추가된 텍스트만 읽어옵니다.
  - 읽어온 텍스트는 기존에 구축된 웹소켓(`wss`)을 통해 접속 중인 모든 사용자(또는 로그인된 사용자)에게 브로드캐스트합니다.
- **[MODIFY] Global State**
  - 활성화된 파일 감시자(watcher)를 관리하는 객체 `const activeWatchers = {}`를 추가하여, 중복 감시를 방지하고 필요 시 중지할 수 있도록 합니다.

### `public/messenger.html`
- **[MODIFY] Frontend Commands**
  - `/monitor [경로]` : 모니터링을 시작하는 명령어 추가. (내부적으로 `/api/monitor` 호출)
  - `/unmonitor [경로]` : 모니터링을 중지하는 명령어 추가.
- **[MODIFY] WebSocket Message Handler**
  - 서버에서 보내주는 `type: 'file-monitor'` 메시지를 수신하여 화면에 깔끔한 터미널/로그 형태로 렌더링합니다.

## Verification Plan
1. `npm run start` 로 서버 시작 후 브라우저 접속
2. `/login admin admin123` 으로 권한 획득
3. 채팅창에 `/monitor logs/2026-03-04.log` 입력하여 감시 시작
4. 다른 브라우저 탭이나 터미널에서 채팅창에 `/log 테스트입니다` 를 입력하면, 해당 로그 파일이 변경됨.
5. 변경된 "테스트입니다" 문자열이 윈도우 파일 시스템 이벤트를 통해 즉시 감지되어 채팅창에 자동으로 출력되는지 확인.
6. `/unmonitor logs/2026-03-04.log` 명령어로 감시 종료 후 추가 로그가 화면에 안뜨는지 확인.
